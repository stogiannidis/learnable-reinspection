Each query is one full probability distribution over all the image patches

Toy version of the re-inspection cross-attention: Q = 6 queries (real model: 64) attending over V image patches (real model: ~1000+). The 6 and the V never have to match — the softmax runs across the patches, so every query gets its own row that sums to 1, whatever V is. Click a row to project it onto the image. Change V and watch nothing break.
1  Dot products One query vector · every patch's key vector → V raw scores (one per patch).
→
2  Softmax across the V patches The V scores become V positive numbers that sum to 1 — a "where am I looking?" map.
→
3  Repeat for every query 64 different query vectors → 64 independent rows. Stacked: the (Q × V) attention matrix.
→
4  KL, row by row Each row (over V) is compared to the bbox target (also over V). Same support → KL is well-defined.

The attention matrix — one row per query, V cells per row

Σ = the row's actual sum (always 1.000). KL = KL(target ‖ row): small when the query's attention sits inside the box (q1–q3), large when it looks elsewhere (q4) or is diffuse (q5). Note the KL never involves "64 vs V" — it compares two length-V rows.
Where this lives in the real code: src/model/reinspection_module.py:97 does softmax(scores, dim=-1) — the last dim is the V image tokens — giving (B, H, Q, V), head-averaged to (B, Q, V) at line 227. src/model/attn_loss.py then re-normalizes each row and the bbox target over that same V axis and takes KL(target ‖ row) per query.

And the catch we discussed: the current loss gives the same target to every supervised query — in this toy, q1, q2 and q3 would all be pulled toward the green target row until they look identical. That's why "each query learns its own corresponding token" needs a different loss design (coverage-of-the-average, matching, or transport), not a different KL formula.
